# 資産管理

家計簿(給与・固定費・大きい出費・貯蓄推移)と、副業会計・確定申告の準備(収入・経費・給与明細・固定資産・仕訳帳など)を1つにまとめた個人用Webアプリです。Googleログインによる Firebase 同期に対応しています。

> **本アプリは公式の確定申告書・税務ソフトではありません。** 画面・印刷・CSVは申告書作成のための参考資料で、税務署への提出書類ではありません。税務上の最終判断は国税庁の案内・税務署・税理士で確認してください。

## ファイル構成
| ファイル | 内容 |
|---|---|
| `index.html` | 画面(サイドバー・ダッシュボード)と副業会計・給与明細・申告準備のロジック |
| `app.js` | 家計簿(元AccountBook)のロジック。副業会計と名前が衝突しないよう内部の変数名を変更し、給与明細・年末調整との連携を追加 |
| `style.css` | 家計簿(元AccountBook)の見た目。`#ab` 配下にだけ適用 |
| `sync.js` | Googleログイン + Firebase(Firestore)同期。元のFirebase設定をそのまま使用 |
| `tests_node.js` / `e2e_browser_test.py` | Node.jsテスト / Chromiumでの実操作テスト |
| `fixtures/accountbook_original_app.js` | 元のAccountBookの `app.js`(合併後との比較テスト用。公開には不要) |
| `.github/workflows/pages.yml` | GitHub Pages への公開設定(`index.html` `app.js` `style.css` `sync.js` を公開) |

## 画面(サイドバー)
- **ダッシュボード**: 家計の集計帯(今月あと使える金額など) + **収益ひと目**(今年の総収益=給与総支給+副業収支+投資損益、給与の手取り、副業の売上・経費・収支、来月の手取り予定) + **月別の推移グラフ**(縦軸に金額目盛り。棒を選ぶと、その月の給与・副業売上・経費・収支・事業別がコメント(吹き出し)で表示)
- **家計・給与**: 給与・振替 / 固定費 / 家計簿 / 大きい出費 / 貯蓄推移 / 設定(元AccountBookの全機能)
- **副業会計・申告**: はじめに / 事業・副業 / 収入 / 支出・経費 / 給与明細 / 事業主貸借 / 固定資産 / 投資取引 / 仕訳・帳簿 / 申告準備 / 勘定科目 / 期首残高 / 手動仕訳 / CSV取込 / データ・テスト / 確認事項
- サイドバーは画面の高さに合わせて項目が縮み、**スクロールバーは出ません**。スマートフォンでは「☰ メニュー」で開閉します。

## 給与・年末調整(二度手間をなくす仕組み)
1. **給与明細**タブで、総支給・健康保険料・厚生年金保険料・雇用保険料・源泉所得税・住民税・年末調整の還付を**別々に**入力します(賞与は区分「賞与」)。
2. 入力した給与明細(区分「給与」)は、家計の「設定」→「実績比率の計算表」に**自動で入り**、来月以降の手取り予測の比率に使われます(給与明細に入力すれば、実績比率表への再入力は不要)。
3. 給与明細の入力欄は「予定から入力」ボタンで、家計の給与予定(総支給・各保険料・源泉・住民税)から自動入力できます。実際の明細に合わせて修正して保存します。
4. **12月の還付**: 給与明細タブで「源泉徴収票の源泉徴収税額(確定額)」を入力すると、月次の源泉所得税合計との差を還付(または追徴)として自動計算し、家計の12月の手取り予測に加算します。確定額が未入力の間は「設定」の手入力額を使い、どちらも無い場合は従来どおり賞与の控除にある「所得税還付」項目を使います(二重計上はしません)。
5. 給与は事業売上とは別枠で集計します。副業は勤務先には申告せず、税務署へ自己申告する前提です(申告要否の目安は「申告準備」)。

## データの保存と同期
- 家計簿のデータは `localStorage`(キー `kk2`)、副業会計のデータは IndexedDB に保存されます。元のAccountBook(`hub-personal-japan.github.io`)と同じサイトのため、同じブラウザなら家計簿のデータはそのまま引き継がれます(別のブラウザ・端末へは移りません)。
- 右上の「☁ ログイン」でGoogleログインすると、**家計簿と副業会計のデータを1つにまとめて** Firestore の `users/{uid}/data/main` に保存・同期します(元と同じ仕組み。最後に更新した端末が優先)。同期データが約900KBを超える場合は送信せず「データが大きすぎて同期できません」と表示します。
- ログイン同期を使うと、収入・給与などの財務データが Firebase(Google)に保存されます。Firestoreのセキュリティルール(本人のみ読み書き可)が設定されていることをご確認ください(ルールの内容は本リポジトリでは確認できません)。
- 受信した副業会計データは、日付・金額・ID・参照などを検証してから反映します。不正な場合は適用せず手元のデータを保持します。
- 副業会計は保存に失敗すると画面のデータも元に戻します。「データ・テスト」からJSONバックアップを定期的に保存してください(家計簿の「設定」の書き出しも、副業会計を含む全データを書き出します)。バックアップは「ダウンロードの開始」までで、ファイルが保存されたかはブラウザでは確認できません。

## 会計処理・申告準備
- 売上計上(売掛金)と入金を別仕訳。経費は支払方法(銀行/現金/カード/未払金/個人資金の立替)ごとに仕訳。前年末の残高は翌年に自動繰越。手動仕訳・カスタム勘定科目・事業別集計(帳簿の損益と一致)
- 減価償却: 定額法(平成19年4月1日以後取得・耐用年数2〜16年)のみ、国税庁の償却率表で自動計算(端数処理は未確認の仮計算)。売却・廃棄日の入力は保存できません(未実装)。それ以外の資産は「要確認」に表示
- 源泉徴収: 売上は源泉徴収前の総額で計上し、源泉徴収税額は経費にせず事業主貸で処理(科目の選択・年またぎの帰属年は未確認のため「要確認」)
- **青色申告特別控除の要件チェック**(申告準備): 要件を選ぶと上限の目安(65/55/10万円・適用なし)と、事業所得に区分した事業の控除後の目安を表示。**控除は自動適用しません**。雑所得の事業は対象外として扱います
- 申告要否の目安: 国税庁タックスアンサー No.1900

## 起動・公開・テスト
- 起動: ブラウザで `index.html` を開く(Firebase同期はWeb公開時に利用)
- 公開(GitHub Pages): `index.html` `app.js` `style.css` `sync.js` と `.github/workflows/pages.yml` をコミットし、Settings → Pages → Source を「GitHub Actions」に設定。実データはコミットしない
- `node tests_node.js`: 画面内テスト(計算・仕訳・給与・年末調整・グラフ・保存失敗・復元検証など) + 元のAccountBookとの完全一致テスト + Firebase同期データのテスト
- `python3 e2e_browser_test.py`: Chromiumでの実操作(Firebaseはスタブに差し替え。本物のGoogleログインは未検証)

## 国税庁の一次情報(確認日 2026-10-15)
- 給与所得者の確定申告が必要な場合: タックスアンサー No.1900 https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/1900.htm
- 源泉徴収: No.2793 / 2795 / 2798(https://www.nta.go.jp/taxes/shiraberu/taxanswer/gensen/2795.htm ほか)、No.6929、源泉徴収のあらまし
- 減価償却: 償却率表(https://www.nta.go.jp/law/joho-zeikaishaku/shotoku/shinkoku/070914/pdf/01.pdf ほか)、No.2106 https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/2106.htm
- 青色申告特別控除: 確定申告の手引き https://www.nta.go.jp/publication/pamph/pdf/0021010-076.pdf 、No.2072 https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/2072.htm
- **未確認(反映していません)**: 少額減価償却資産の特例の令和8年度改正(民間解説のみ)、青色申告特別控除の令和9年分以後の変更(民間解説のみ)、源泉徴収税額の勘定科目(事業主貸)と年またぎの帰属年
