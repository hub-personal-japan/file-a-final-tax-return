# 資産管理

家計簿(給与・固定費・大きい出費・貯蓄推移)と、副業会計・確定申告の準備(収入・経費・給与明細・固定資産・投資取引・仕訳帳など)を1つにまとめた個人用Webアプリです。元の「AccountBook」サイトは不要で、この `index.html` 1ファイルだけで動きます(Googleログインによる Firebase 同期も同じ設定のまま内蔵)。

> **本アプリは公式の確定申告書・税務ソフトではありません。** 画面・印刷・CSVは申告書作成のための参考資料で、税務署への提出書類ではありません。税務上の最終判断は国税庁の案内・税務署・税理士で確認してください。

## 画面
- **サイドバー**: 「資産管理」の表示はサイドバーのロゴのみ。画面の高さに合わせて項目が縮み、スクロールバーは出ません(スマートフォンは「☰ メニュー」)。
- **ヘッダー**: 開いている項目の名前と説明を表示します。
- **ダッシュボード**: 上段は**現在の総資産**を大きい主役タイルにした家計の集計帯 → 今年の収益は**給与の手取り**を大きい主役タイルにし、その下に月平均(手取りの累計 ÷ 現在の月)を表示 → 副業・申告の確認 → 月別の推移(縦軸に金額目盛り。**同じ月の給与(金)と賞与(紫)は縦に積み上げて合計を表示**、副業の売上は赤・経費は緑。棒を選ぶと詳細が吹き出しで表示)+ 事業別・投資・経費カテゴリ。各集計は1行です。
- **画面サイズ**: 1280×853・1440×960・1512×1008・1920×1080で、ダッシュボードと家計・給与の各タブが1画面に収まることを確認しています。画面が大きいほど全体を自動で拡大します(幅÷1440と高さ÷880の小さい方・最大1.6倍。ブラウザの `zoom` 機能を使うため、Chrome・Edge・Safari・Firefox 126以降が対象)。
- **色**: プラスは赤、マイナスは緑(日本の株式と同じ向き)です。要確認の件数などの状態表示は琥珀色で、損益の色とは分けています。
- **今月あと使える金額**: 今月の給与日(25日。土日は前の平日)までの期間で計算します(今月の給与と、前回の給与日の翌日から今日までの支出)。家計簿タブの予算(締め日15日の期間)とは別の基準です。
- **家計・給与**(元AccountBookの全機能): 給与・振替 / 固定費 / 家計簿 / 大きい出費 / 貯蓄推移 / 設定。副業会計と同じデザイン・同じ文字サイズ・金額の右そろえ(一の位がそろう)に統一しています。
- **副業会計・申告**: はじめに / 事業・副業 / 収入 / 支出・経費 / 給与明細 / 事業主貸借 / 固定資産 / 投資取引 / 仕訳・帳簿 / 申告準備 / 勘定科目 / 期首残高 / 手動仕訳 / CSV取込 / データ・テスト / 確認事項

## 給与・年末調整(二度手間をなくす仕組み)
1. **給与明細**で、総支給・健康保険料・厚生年金保険料・雇用保険料・源泉所得税・住民税・年末調整の還付を別々に入力(賞与は区分「賞与」)。支払者は一度入力すると候補・選択ボタンから選べ、新規入力では直前の支払者が最初から入ります。
2. 入力した給与明細(区分「給与」)は、家計の「設定」→「実績比率の計算表」に自動で入り、来月以降の手取り予測の比率に使われます。
3. 「予定から入力」で、家計の給与予定を入力欄に転記できます。
4. **12月の還付**: 給与明細タブで源泉徴収票の確定税額を入力すると、月次の源泉所得税合計との差を還付(または追徴)として自動計算し、12月の手取り予測に加算します(未入力の間は「設定」の手入力額、どちらも無い場合は賞与の控除にある還付項目。二重計上しません)。
5. ダッシュボードの「来月の手取り」は、給与・振替タブの翌月の給与手取りと同じ計算結果です。

## 投資取引(デイトレード・SBI証券CSV)
- 商品に「デイトレード」を追加。「デイトレードの収益」に、合計・今月・取引日数・勝ち負け日数・最大益/最大損・手数料・源泉徴収額・税引後の手取りを表示します。
- **SBI証券のCSV取込**(約定履歴・国内株式の現物と信用): Shift_JIS/UTF-8を自動判別。前置きの行を読み飛ばして見出し行を検出し、買いと売り(信用は新規と返済)を**先入先出**で対応付け、手数料を引いた実際の利益を投資取引に追加します。当日に完結した取引は「デイトレード」、それ以外は「現物株」「信用取引」。口座の既定は「特定口座(源泉あり)」(預り区分がNISA・一般の行はそれぞれ別口座)。CSVの税額列は源泉徴収額として記録します。
- **重複チェック**: 約定日・銘柄・売買・数量・単価で判定し、同じ取引は何度取り込んでも二重になりません(同じ内容の約定が複数ある場合は件数も数えます)。取り込んだ損益は再取込のたびに作り直されます(手動で直した内容は上書き)。
- 取得価額は先入先出の簡易計算で、特定口座の総平均法とは異なる場合があります。実際の損益は年間取引報告書で必ず確認してください。**実際のSBI証券のCSVは確認していないため、列名は既知の見出し(約定日・約定数量・約定単価・手数料/諸経費等・税額・決済損益など)で判定しています。読み込めない場合は、CSVのサンプルをお知らせください。**

## データの保存と同期
- 家計簿は `localStorage`(キー `kk2`)、副業会計は IndexedDB に保存されます。元のAccountBookと同じホスト(`hub-personal-japan.github.io`)なので、同じブラウザなら家計簿のデータはそのまま引き継がれます。**元のサイトを削除する前に、「設定」の書き出しでバックアップを保存してください。**
- 右上の「☁ ログイン」でGoogleログインすると、家計簿と副業会計のデータを1つにまとめて Firestore(`users/{uid}/data/main`)に保存・同期します(最後に更新した端末が優先。約900KBを超えると送信せず警告)。Firestoreのセキュリティルール(本人のみ読み書き可)が設定されていることをご確認ください。
- 副業会計は保存に失敗すると画面のデータも元に戻します。受信・復元するデータは日付・金額・ID・参照を検証してから反映します。バックアップは「ダウンロードの開始」までで、保存されたかはブラウザでは確認できません。

## 起動・公開・テスト
- 起動: `index.html` をブラウザで開く
- 公開(GitHub Pages): リポジトリに `index.html` と `.github/workflows/pages.yml` をコミットし、Settings → Pages → Source を「GitHub Actions」に設定。実データはコミットしない
- `node tests_node.js`: 画面内テスト(計算・仕訳・給与・年末調整・グラフ・SBI取込・保存失敗・復元検証など) + 元のAccountBookとの一致テスト(今月あと使える金額の基準と総資産の強調だけは意図して変更) + Firebase同期データのテスト
- `python3 e2e_browser_test.py`: Chromiumでの実操作(`index.html` だけを配信して確認。Firebaseはスタブに差し替え)
